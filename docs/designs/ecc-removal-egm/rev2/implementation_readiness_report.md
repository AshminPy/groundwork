## Blockers

**B-1. The bench copy is isolated for the config dir only (tasks 7.1, 7.2, 7.4, 1.5; design Risks line 354). Verified in code.** Four separate leaks, one root cause:
1. *Hook commands.* `scripts/merge_settings.py:50-80` hard-codes `python3 ~/.claude/hooks/...` and `~/.claude/groundwork/bin/...`. `CLAUDE_CONFIG_DIR=~/gw-bench/g-ecc-off ./install.sh` copies new hooks into the bench dir, but the bench `settings.json` still runs the real `~/.claude/hooks/*`, which are the old files until task 8.3. The edit-guard scenarios (c) no-verify and (d) ruff.toml test old guards; `tokens` and the reviewer are never exercised; the on/off comparison is confounded. (IR N-B1)
2. *launchd.* `install.sh:111-112` runs `groundwork_report.py schedule` on macOS. `LABEL = "com.groundwork.report"` is global (`groundwork_report.py:43`) and the plist goes to `~/Library/LaunchAgents` (`:635`), so a bench install repoints the owner's real weekly job at the bench copy; `setup.sh:854` (rollback) runs `schedule disabled` and removes it. The code has overrides, `GROUNDWORK_NO_LAUNCHCTL` (`:655`) and `GROUNDWORK_LAUNCH_AGENTS_DIR` (`:635`), but no task uses them. (CB B2)
3. *Shell and npm.* `install.sh:170` writes the real `~/.bashrc`, `~/.zshrc`, `~/.profile`; `install.sh:81` runs `npm install -g` for OpenSpec. (IR N-M7)
4. *Wording.* 7.2 says "with `CLAUDE_CONFIG_DIR=…`", which can be read as an argument. "That backup" does not say which of `~/.claude-backups` or a bench root. 7.1 checks the real dir only after the run. 8.3 runs `./install.sh` on the real Mac without checking `CLAUDE_CONFIG_DIR` is unset. (SW S-B1)
- Fix: add a task before 7.1 that (a) makes hook commands relative to the target dir, or rewrites the bench `settings.json` and then greps it for `~/.claude/` (zero hits); (b) sets `GROUNDWORK_NO_LAUNCHCTL=1`, a scratch `GROUNDWORK_LAUNCH_AGENTS_DIR`, and a scratch `HOME`; (c) sets `GROUNDWORK_BACKUP_DIR` to a bench root; (d) records the real `plugin list --json`, `settings.json` hash, plist mtime and rc-file hashes before, and compares after. Write every command with its environment on the same line.

**B-2. The installed `setup.sh` cannot source `scripts/backup.sh` (tasks 5.1, 5.3; design D6 line 306). Verified in code.** `install.sh:138` copies `setup.sh` alone to `$CLAUDE_DIR/groundwork/bin/`; `setup.sh:26` sets `HERE` to that bin directory; under `set -euo pipefail` a missing `source` kills the script. `groundwork rollback` and `groundwork doctor` (`groundwork_update.py:74`) run that copy, so the primary offline rollback and `--doctor` break. The `--verify` list "from `merge_settings.py`" is also unreadable there (`scripts/` is not copied). `backup.sh` also depends on `ts`, `BACKUP_ROOT`, `CLAUDE_DIR`, `BACKUP_PATH` defined in `setup.sh`, and Python (`migrate_off_ecc.py`) cannot source it. Fix: copy `backup.sh` into `bin/` (remove in `uninstall.sh`), source from the script's own directory, define the call interface (for example `bash backup.sh <config dir> <root>` printing the path), put the expected hook list in a file also copied to `bin/`, and add a test that runs `--rollback` and `--doctor` from an installed tree. (CB B1, IR N-M2, N-M4)
